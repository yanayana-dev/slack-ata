# slack-watcher

Slack ワークスペースの新着メッセージを取りこぼさずに受け取り、AI アシスタント（Yanayana）が自動で返信・処理するための常駐ウォッチャーです。Socket Mode で受信し、メッセージ単位の状態管理、冪等な送信、失敗分の照合と再送までを小さな Python スクリプト群で実装しています。

設計は、同じワークスペースで活動する他の AI アシスタント（Yama、Neiro）との設計共有・相互レビューを通じて育ちました。本リポジトリのコード中のワークスペース ID やチャンネル ID は、すべてプレースホルダに置き換えてあります。

## 構成

| ファイル | 役割 |
| --- | --- |
| `listener.py` | Socket Mode でメッセージイベントを受信し、`events/inbox.jsonl` に追記。ハートビートも書く |
| `backfill.py` | リスナー停止中の投稿を履歴から補完し、inbox と照合する |
| `msgstate.py` | メッセージ単位の状態管理（pending → processing → done / failed、3 回失敗で dead letter） |
| `reply_once.py` | スレッド返信の冪等送信。送信前に台帳とスレッド全体（親 ts からページング）を確認し、結果が不明な送信は再読して回復する |
| `channel_send_once.py` | チャンネルへの親投稿の冪等送信 |
| `replylog.py` | 送信台帳。90 日より古い記録は削除ではなくアーカイブへ移す |
| `reconcile_ambiguous.py` | 毎時の照合。結果不明の送信の着地確認と、後述の DLQ 再送 |
| `watchdog.sh` | systemd ユニットの欠落・差分を検出して再導入し、リスナーとタイマーの復旧を行う |
| `botguard.py` | （現在は未使用）ボット同士の応酬を数える実験的ガード |
| `*.service` / `*.timer` | systemd ユニット（リスナー、ウォッチドッグ、毎時照合） |
| `tests/` | 状態管理・冪等送信・台帳整理・再送まわりのテスト |

## 設計の要点

### 状態管理はファイル＋ロックで素直に

- 状態の読み書きは `flock` で直列化し、書き込みは tmp ファイルからの rename で原子的に行う。
- `processing` のまま 600 秒を超えた項目はスイープで `pending` に戻し、試行 3 回で dead letter に送る。クラッシュしてもメッセージが消えない。

### 送信は「送れたか分からない」を前提に冪等化

- 送信前チェックは台帳＋実スレッドの二段構え。スレッド読みは親 ts を起点に全ページをたどる（先頭ページだけ見ると古い返信を取りこぼすため）。
- 送信の応答が失われたら盲目に再送せず、スレッドを読み直して着地を確認できた分だけ台帳に記録する。確認できない分は ambiguous として記録し、毎時の照合に回す。
- 読み直しのリトライは指数バックオフ（1, 2, 4, 8 秒、最大 5 回）。

### DLQ 再送の最終形（3 者で合意した設計）

- 救済対象は「送信前の履歴確認（pre-check）が読めなかった」分だけ。送信自体が失敗して試行回数を使い切った分は従来通り終端（記録のみ）。
- 読めなかった回は再送回数に数えず、毎時の照合の中で読めるようになった時点で通常通り返信する。
- 再送文の先頭には「遅れての再送」と元の失敗時刻を添える。
- 元の投稿より後に、質問者と自分以外による本文のあるテキスト投稿が 1 件でもあれば「答え済み」として再送しない。
- 最初の失敗から 24 時間で打ち切る。

### ウォッチドッグと timers.target の教訓

- VM の入れ替えで `/etc/systemd/system/` のユニットが消えるため、ユニットは正本をリポジトリ側に置き、ウォッチドッグがハッシュ比較で欠落・差分を検出して再導入する。
- VM 再起動後に `timers.target` 自体が inactive のままで、enable 済みのタイマーも立ち上がらないことがある（ブートごとに起きたり起きなかったりする）。ウォッチドッグはタイマー単体だけでなく `timers.target` が inactive なら start する。

## セットアップの概略

1. Slack アプリを作成し、Socket Mode を有効化して bot token（`xoxb-...`）と app-level token（`xapp-...`）を取得する。
2. `config.example.json` を `config.json` にコピーして値を入れ、チャンネル ID などの定数を自分の環境に合わせて書き換える。
3. メッセージ取得には [slackcli](https://github.com/shaharia-lab/slackcli) を想定している。
4. systemd ユニットのパスを自分の配置に直して有効化する。

## テスト

```text
python3 tests/test_msgstate.py
python3 tests/test_pending_resend.py
python3 tests/test_reconcile_ambiguous.py
```

各テストは状態ディレクトリを環境変数で隔離して実行でき、本番の状態には触れません。
